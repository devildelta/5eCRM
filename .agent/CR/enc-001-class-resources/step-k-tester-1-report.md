## K-T001 auditor follow-up — Rage

**Expected:** The shared-pool rule and K-T001 require one Barbarian Rage pool, keyed `class:barbarian:rage`, with `shared:true`; Rage-using subclass features consume that same pool and must not create duplicate Rage pools. The recovery reference identifies Rage as the pool used by multiple subclass abilities (`.agent/CR/class-resource-recovery-reference.md:39–47,203–204,240`), and the plan names Rage as a shared resource (`.agent/CR/CR-class-resources-plan.md:21,236`).

**Runtime actual:** On the isolated HTTP origin, configured a single Barbarian level 19 character, all abilities 14, PB +6, and applied each supported Barbarian subclass in turn (Berserker, Totem Warrior, Ancestral Guardian, Storm Herald, Zealot, Beast, Wild Magic, Path of the Giant). Every generated set contained exactly one `class:barbarian:rage` row: current/max 6/6, maximum formula `{type:"barbarian-rage"}`, long-rest recovery, PHB source, `shared:false`, `consumers:[]`, `costs:[]`. No other generated key contained `rage`. Ancestral Guardian separately generated `subclass:barbarian:ancestral-guardian:consult-the-spirits`; Wild Magic separately generated `subclass:barbarian:wild-magic:bolstering-magic`; neither was a Rage duplicate or linked cost.

**Consumer-link check:** The expected rules-level relationship is that Rage-dependent subclass features use this one pool.
