# CR 模組 UX 與架構改進計畫

- **Owner**：使用者
- **Co-author**：GitHub Copilot
- **狀態**：計畫文件；待使用者審閱後開始實作
- **範圍**：僅 CR（Character Resource）資源管理頁
- **主要情境**：桌上遊戲中快速查看、消耗與回復角色資源

## 目標

1. 讓目前角色與資源剩餘次數成為頁面焦點，優先支援遊戲中的快速操作。
2. 將低頻管理收進管理介面，提供可取消且不會意外丟失資料的新增/修改流程。
3. 移除 inline event handlers，讓事件綁定與 HTML/呈現分離。
4. 採用原生 ES modules 按責任拆分程式碼，不引入框架、建置工具或套件流程。
5. 保留 localStorage、既有角色/資源資料與 Base64 匯入匯出相容性。
6. 減少結構操作不必要的整清單 DOM 更新；不把現況已局部更新的操作誤列為效能問題。

## 現況與 UX 評估

角色操作、匯入匯出、新增表單、休息回復及每項資源的所有管理按鈕目前都平鋪在主頁，讓主頁偏向管理表單，遊戲中最常用的資源狀態和消耗操作不夠突出。桌面沿用通用 Bootstrap 欄位配置，沒有明確的內容寬度與資源排列策略；手機版普遍放大所有按鈕，操作層級容易失焦。

建議主頁以「角色列 → 休息回復工具列 → 資源清單」呈現。資源項目優先顯示名稱、剩餘/最大次數與冷卻；「使用」作為主要高頻動作，單項回復保留直接入口，複製/修改/刪除集中在管理介面。管理介面可分為資源、角色、匯入/匯出區。桌面設定有上限的內容寬度與較高資訊密度；窄螢幕使用清楚的一欄排列和足夠觸控尺寸。按鈕採一致語意，但不只靠顏色區分功能。

> **DOM 更新現況**：`use()`、`resetOne()`、`resetCooldown()` 已透過 `refreshSkillAt()` 更新受影響的資源。新增會追加新卡片。全清單重畫主要發生於複製、修改、刪除、角色切換及匯入；優化聚焦在結構變動操作。角色切換與整批匯入可保留完整重建。

## 執行計畫

### 階段 0：確認基線與方案

- [ ] **代理可執行**：盤點 CR 互動、資料欄位、`dnd_skills_db` key、匯入匯出格式、DOM 更新路徑及頁面依賴。
- [ ] **代理可執行**：確認 Bootstrap 版本、可用的對話框能力，以及現有瀏覽器驗收方式；不新增測試框架。
- [ ] **代理可執行**：將已定案範圍寫入實作依據：不修改 `index.html`、不碰未上線模組與其 `.agent` 文件。
- [ ] **需要使用者指示（若與建議不同）**：主頁是否保留單項回復；建議保留，以支援即時遊戲操作。
- [ ] **需要使用者指示（若與建議不同）**：複製/修改/刪除資源是否集中在管理介面；建議集中，降低遊戲中誤觸。
- [ ] **需要使用者指示（若與建議不同）**：角色建立是否留在主頁；建議角色選擇留在主頁，建立入口也保持容易找到。

**完成條件**：CR 現況及資料相容性基線已確認；未有使用者另行指示時，按以上建議進行，不因非必要選項阻塞實作。

### 階段 1：主頁與管理資訊架構

- [ ] **代理可執行**：調整 `cr.html`，建立角色列、休息回復工具列、資源清單與管理入口。
- [ ] **代理可執行**：管理介面分為資源、角色、備份（匯入/匯出）區；新增與修改資源共用表單，提供明確取消。
- [ ] **代理可執行**：修改資源時保留原始資料直到使用者確認儲存；取消修改不得移除原資源，修正目前 `edit()` 先刪除再編輯的風險。
- [ ] **代理可執行**：提供未選角色、空資源清單等狀態；刪除角色/資源等危險操作仍須確認。
- [ ] **需要使用者人工驗收**：確認在不開管理介面的情況下，可完成查看次數、消耗、單項回復與每回合/短休/長休回復。

**完成條件**：高頻遊戲操作留在主頁，低頻管理集中；開啟、取消及確認操作均有清楚結果。

### 階段 2：視覺層級與響應式版面

- [ ] **代理可執行**：調整 `src/cr.css` 的內容最大寬度、字級層次、間距、桌面資源欄數及手機斷點。
- [ ] **代理可執行**：統一主要操作、一般操作、回復/休息與危險操作的按鈕語意；搭配文字或圖示，不以顏色作唯一提示，並檢查對比。
- [ ] **代理可執行**：固定資源資訊與控制項的排列，避免長名稱、次數、冷卻和按鈕互相推擠；手機保留足夠觸控區。
- [ ] **代理可執行**：管理介面在窄螢幕不超出 viewport，內容可內部捲動；表單欄位有可見標籤和合理輸入型態。
- [ ] **需要使用者人工檢查**：在手機、一般桌面及寬桌面檢查資訊密度與操作手感，特別確認原先桌面「太細/空間沒用好」的不適是否改善。
- [ ] **需要使用者指示**：若視覺方向不符合預期，描述希望優先調整的密度、排列或視覺語氣；建議維持低干擾、高可讀的遊戲工具感。

**完成條件**：窄手機、平板、一般桌面與寬桌面均無文字溢出、操作重疊或主要操作難以定位的問題。

### 階段 3：事件綁定與程式模組邊界

- [ ] **代理可執行**：移除 `cr.html` 及動態資源卡片中的 inline `onclick`。
- [ ] **代理可執行**：在 CR 頁面容器註冊事件委派，使用 `data-action` 與資源識別值分派操作，不再依賴全域 onclick 函式。
- [ ] **代理可執行**：將頁面入口改為 ES module，按實際責任拆分頁面控制、資料存取/序列化和 DOM 呈現。候選檔案為 `src/cr.js`、`src/cr-storage.js`、`src/cr-view.js`；若拆分未降低耦合，維持較少檔案，不為拆分而拆分。
- [ ] **代理可執行**：評估以穩定資源 ID 取代陣列 index 作為事件識別；只有確實需要時才加入，且舊資料讀取、匯入和保存須相容。
- [ ] **代理可執行**：匯入資料先做必要結構檢查，錯誤資料不可部分覆蓋現存資料；保留現有 localStorage key 與欄位。
- [ ] **代理可執行**：不引入框架、bundler、`package.json` 或整站 SPA。
- [ ] **需要使用者人工操作**：透過 HTTP(S) origin 開啟 CR 驗證 ES modules；不以 `file://` 作模組載入驗收。

**完成條件**：CR 沒有 inline handlers；模組責任清楚；舊資料可載入、保存、匯入與匯出；瀏覽器沒有相關 console errors。

### 階段 4：局部 DOM 更新與資料操作

- [ ] **代理可執行**：消耗、單項回復及休息回復只更新受影響資源的顯示節點。
- [ ] **代理可執行**：新增/複製插入或更新受影響項目；刪除只移除目標項目；修改只更新目標項目，不清空整份清單。
- [ ] **代理可執行**：角色切換和整批匯入可重建整份清單，因為資料來源整體改變。
- [ ] **代理可執行**：驗證次數不低於 0、不超過 max；休息回復遵守目前每回合、短休、長休規則；不擅自改動日出/每24小時行為。
- [ ] **需要使用者指示（若要改變既有行為）**：匯入重名角色維持逐項覆蓋確認，或改為全部覆蓋/略過。預設沿用既有逐項確認。

**完成條件**：CRUD 與回復正確；常用操作不重繪其他資源；資料和畫面保持一致。

### 階段 5：回歸驗收與交付

- [ ] **代理可執行**：使用 HTTP(S) 驗證模組載入、無 console errors，以及刷新後資料持久化。
- [ ] **代理可執行**：驗證既有 Base64 資料可匯入、匯出及複製；取消匯入/修改不改資料；重名覆蓋/略過遵守既定行為。
- [ ] **代理可執行**：逐項檢查角色建立/切換/複製/刪除、資源新增/修改/取消/複製/刪除、消耗、單項回復及各種休息回復。
- [ ] **需要使用者人工驗收**：以自己的角色資料走過主要工作流程；可先匯出備份，避免測試影響既有資料。
- [ ] **需要使用者人工驗收**：在實際手機/桌面或對應視窗尺寸檢查版面、觸控尺寸、管理介面捲動、鍵盤焦點、Tab、ESC/關閉、文字溢出與按鈕辨識。
- [ ] **需要使用者指示**：確認視覺密度和操作分組符合預期；若不合用，調整後再完成驗收。
- [ ] **需要使用者人工操作**：每個實作階段及聚焦驗證完成後，審閱差異並提交該階段 commit；代理不會未經要求代替使用者提交實作階段。

**最終完成條件**：功能回歸與資料相容性確認；人工 UX 驗收完成；工作區差異可審查，實作階段提交均由使用者確認。

## 決策摘要

- 本次僅處理 CR；不改 `index.html`、未上線模組及其 `.agent` 文件，也不做整站改版。
- 保留 `dnd_skills_db` localStorage key 與現有匯入/匯出相容性；不做無需求的 schema 變更。
- 採原生 ES modules，不新增框架、建置工具、套件或測試框架。
- 多頁工具集是未來建議：首頁可作工具目錄，各工具保留獨立頁面；這與每個工具提供單頁式操作體驗不衝突，也不代表整站必須採 SPA。
- `.agent/dice/` 中的規則屬於另一模組，本計畫不套用、不修改。
