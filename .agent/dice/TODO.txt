D&D 5e 傷害規則及骰式支援
- 傷害分佈按來源拆分
  - 目標：除總傷害分佈外，按傷害來源區分各傷害桶的機率，例如普通命中、爆擊，以及消耗每輪 PR 池的命中。
  - 設計要求：保留來源分類的同時維持正確的聯合機率；明確處理同一傷害值可由多個來源產生，以及多次攻擊中 PR 池只會由每輪首次命中消耗的情況。
  - 後續：設計可供圖表及結果摘要使用的來源分佈資料形狀，並加入來源機率總和與總分佈一致性的驗證。
- D&D 5e 重擲規則（優先 GWF 重擲 1、2）
  - 目標：支援 D&D 5e 常用的重擲效果，首個具體案例為 Great Weapon Fighting 重擲傷害骰的 1 或 2。
  - 設計要求：以非均勻 PMF 表達重擲後的骰子分佈；釐清重擲次數、可重擲條件及爆擊骰的處理方式。避免引入 D&D 5e 範圍以外的通用骰制機制。
  - 現狀：GWF 支援曾經回滾，尚未實作。

單一建構計算與比較介面
- 多建構結果比較流程
  - 目標：先穩定單一建構的計算介面及結果形狀，再由上層依序計算建構清單，回傳每個建構的傷害 PMF、命中率、四分位數及理論上限，供排序、比較及高階分析使用。
  - 設計要求：每次單一計算只接收一個建構／攻擊設定；建構之間的差異由上層迭代處理，不把多個設定混入同一條攻擊序列。
  - 後續：以 Sharpshooter 等建構差異作為比較流程的驗證案例；避免依賴舊版只接受數值 toHit 的介面。

計算資源及輸入保護
- 可行計算量限制
  - 目標：在開始計算前估算輸入會展開成的骰數、攻擊／輪次數、PMF span、直接摺積工作量及 FFT 記憶體需求；超出預算時回報可理解的輸入錯誤。
  - 驗證：以基準測試及目標裝置的時間／記憶體預算決定上限，並測試上限內可完成、超限輸入會快速拒絕。
  - 現狀：已實作 600 顆骰／摺積池、300 顆基礎傷害骰／次計算、300 次打擊、300 輪及 100,000 個 PMF 桶位上限。Node.js v24.20.0 上完整計算 `(300D4)` 約 171 ms；目標低階瀏覽器裝置仍需另行基準驗證。

每輪一次（PR）資源語義
- PR 多資源與觸發條件規格檢視
  - 現狀：目前模型為每輪一個共享 PR 池，由該輪第一個命中消耗；模型雖已用狀態分佈計算，仍未代表所有 5e 能力的資源語義。
  - 目標：在增加支援前，先確認多個獨立 PR 池、不同觸發方式、適用打擊限制及爆擊互動的規則需求，並訂明清晰的公式表示法。
